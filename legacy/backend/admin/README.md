# 多平台弹幕统一推送服务与监管控制面板

## 模块功能边界定义

本模块负责运营一个WordToFlush backend admin前端面板，使用flask技术栈构建

旨在打通“前端参数修改与控制”与“后端的运行时变量或参数实时修改与业务执行”

这个模块需要被包含在backend的docker镜像中，在同一容器下部署运行，但是需要与backend的业务功能与托管代码解耦

该模块在容器内部固定监听8001（backend的固定监听端口是8000），绑定到宿主机的端口号必须要能够且仅能够在backend/.env中设置

这个模块的具体业务功能是：在flask托管的前端页面中可以直接填写抖音/bilibili的用户ID（尤其是例如抖音，用于认证访问直播间）与我们唯一的房间号

随后使用dy/bilibili文件夹下的业务服务抓取各自平台直播间的所有弹幕发言用户名+发言内容（具体要求如下有说明）

这个模块需要将多平台接收到的符合要求的用户弹幕，以下述的指定结构清洗后，直接返回到前端，前端需要实时同步来自后端推送的全平台弹幕信息

然后前端需要自动加载用户输入（包含用户名与发言内容，注意保持现有的“发言内容字数只接受与问题词字数一致”的规则）并进行现有的判定流程（不用手动在现有文本框“输入用户名和猜的词汇”而直接实现这个业务）

## 现有代码资源与实现需求

目前backend/admin/ 目录（即本文件所在目录位置）下有dy与bilibili两个子目录

其中：

 - dy目录下为一个完整的开源抖音直播监视项目，我们需要移除所有不必要的部分，只需要提取用户名+弹幕纯汉字文本内容即可（包含非汉字文本内容的直接忽略）
 - bilibili目录下有一个bilibili官方弹幕获取的公开API调用说明文档，接下来需要实现提取用户名+弹幕纯汉字文本的业务功能代码（提取结果的处理规则同上）
